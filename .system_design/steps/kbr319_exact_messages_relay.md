# KBR-319 — Exact Claude Code Messages relay

## Planned delivery

For an eligible subscription backend on `/v1/messages`, retain the incoming JSON bytes and end-to-end headers, forwarding them directly to Anthropic. The raw relay bypasses translation, model replacement, compaction, request mutation, synthetic authorization, and token refresh. It supports normal and SSE responses; it preserves an incoming `x-api-key` but never synthesizes one.

## Decisions and why

- **Relay raw bytes, not decoded JSON.** `request.json()` plus `json=` changes whitespace, ordering, escapes, and duplicate-key behavior, so it cannot meet the byte-preservation contract.
- **Forward end-to-end headers, with transport exceptions.** OAuth authorization and Anthropic feature/version headers are part of Claude Code's request. Authority, hop-by-hop headers, and HTTP framing are invalid across the localhost-to-Anthropic hop and must be regenerated by the HTTP client.
- **Do not expose raw relay on other ingress protocols.** Those clients cannot form a native Claude Code OAuth Messages request; translating them would violate the subscription boundary.

## Implementation notes

Landed on feat/kbr-319-anthropic-subscription. `_handle_messages` branches to `_relay_subscription_messages` for
subscription backends (raw bytes via cached `request.read()`, `data=` post, end-to-end headers minus the 10-entry
stripped set, no `x-api-key` synthesis). Non-streaming success returns upstream bytes verbatim (+ request-id);
streaming pumps SSE verbatim; failures raise UpstreamError into the Messages-dialect envelope. Other ingress routes
reject subscription backends with a 400 configuration error. 15 L3 tests in
tests/bridge/test_subscription_messages_relay.py. Reviewed: code-reviewer APPROVE (R7/R8/R11).

Review round (2026-10-18, PR #294 CI review): a relay read timeout (`ServerTimeoutError`) escaped
`_is_transport_error` (which deliberately excludes `asyncio.TimeoutError`) and the handler's only
`except UpstreamError`, surfacing as a raw aiohttp 500. The handler's subscription branch now catches
`asyncio.TimeoutError` and answers the translated path's 504 `api_error` envelope, parking no backend and failing
over to none — the semantics the owner chose to mirror from the translated Messages path (§16.1 records it). Mid-stream
SSE failures were already contained inside `_relay_subscription_messages_stream` (`stream_failed`), so the new arm
only ever sees pre-emission timeouts. Two L3 tests pin the 504 envelope and the no-parking semantics
(tests/bridge/test_subscription_relay_health.py).
